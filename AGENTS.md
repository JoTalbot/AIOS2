# Инструкции для AIOS агентов

## Назначение
Этот репозиторий содержит AIOS и изолированную новую архитектуру на ветке `new`. Перед каждым изменением агент обязан прочитать `AGENTS.md`, `.agents/STATUS.md` и подходящие skills.

## Параллельная работа
- Работа выполняется разными агентами, с разных машин и параллельно.
- GitHub — источник истины для кода, документации и статуса.
- Перед каждым существенным шагом проверяйте `.agents/STATUS.md` и открытые PR/issues.
- Один агент — ограниченный ownership файлов/подсистемы; не переписывать чужую историю.
- Не делать force-push в общие ветки.
- Завершённый атомарный шаг: тесты/валидация → commit → push → обновление статуса.

## Новая архитектура
- Вся работа по новой архитектуре выполняется в ветке `new`.
- Сохранять единый execution/persistence/recovery path.
- Не создавать параллельные stores, execution state или recovery mechanisms без ADR.
- Любое изменение публичного контракта сопровождается regression test.

## Skills
Перед реализацией проверить `.agents/skills/`. Успешные решения, архитектурные паттерны и устранённые проблемы превращать в reusable skill.

## Исследование
Перед существенным изменением исследовать существующую реализацию, документацию и релевантные решения; зафиксировать архитектурное решение в docs/ADR или research note.

## Handoff
После каждого существенного шага обновлять `.agents/STATUS.md`: активный агент, задача, завершённое, изменённые файлы, проверки, блокеры и следующий шаг. Новый агент должен продолжить работу без предыдущего чата.

## Definition of Done
1. Проверены и применены relevant skills.
2. Проведено необходимое исследование.
3. Добавлены/обновлены regression tests.
4. Пройдены доступные проверки.
5. Документация и status обновлены.
6. Изменения закоммичены и отправлены в GitHub.
